# プレイヤーの参加と再接続

通常ボタンで参加し、プレイヤーごとに接続中の `Controller` 参照を割り当てます。接続 token をプレイヤー番号として保存しません。

## 導入

1. Package Manager で「プレイヤーの参加」を Import します。
2. 操作する GameObject をプレイヤーごとに用意します。
3. 空の GameObject に `PlayerJoinExample` を追加します。
4. `players` に各 GameObject の Transform を割り当てます。
5. Input System の更新方式を既定の Dynamic にします。
6. 各コントローラーで A を押して参加します。

## 操作と割当

A の押下で先頭の空きスロットへ参加します。保持だけでは参加しません。既に割り当てた接続の A は、別のスロットへ重複割当しません。満員なら新しい参加を無視します。

左スティックで、そのプレイヤーの Transform をワールド座標に沿って移動します。B の押下は、そのプレイヤー番号をログへ出します。同じ操作を別の PlayerInput と重ねて処理しないでください。

`GetController(0)` はプレイヤー1の接続を返します。未参加、切断、範囲外のスロットは `null` を返します。ゲーム側の処理も、そのプレイヤーに割り当てた参照から入力を読んでください。

切断でそのスロットだけを空けます。他のプレイヤーの割当は保持します。再接続した装置は、新しい A の押下で再参加します。以前と同じスロットになる保証はありません。ライブラリは古い参照を中立化します。

サンプルの無効化、または `players` の要素数の変更で割当を解除します。再度 A を押して参加してください。この例は振動を開始しません。

前提の Issue #6 は、承認された2台の合成検証で完了しました。複数実機の入力・振動は未検証です。

```powershell
pwsh -NoProfile -File Tools/Test-PlayerJoinSample.ps1
```

実サンプルと実 Controller を合成状態で検証します。Unity、GameInput、デッドゾーンは代役です。Unity Play、Import、画面表示、複数実機操作は別途確認が必要です。
