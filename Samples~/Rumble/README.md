# モーター別の振動

公開 API と Unity IMGUI で、先頭の接続へ振動を要求します。汎用効果エンジンは追加しません。

## 導入

1. Package Manager で「モーター別の振動」を Import します。
2. 空の GameObject に `RumbleExample` を追加します。
3. Inspector で強度と秒数を指定します。既定値は `0.25`、`0.7` 秒です。
4. Play で画面のボタンを押します。

本体低周波、高周波、左右トリガーを個別に要求できます。同時要求は対応モーターだけを使います。Unity Gamepad 経路は本体2モーターです。GameInput 経路は装置の対応情報に従います。

## 要求と停止

`Play(low, high, leftTrigger, rightTrigger, seconds)` は API 受付時に `true` を返します。非対応出力、非有限値、非正の時間は拒否します。拒否時は進行中の要求と期限を保持します。

同じ接続への新しい要求は強度と期限を置き換えます。接続を変更する要求が成功したら、以前の接続を停止します。重ね合わせは行いません。

期限は非スケール時間を使います。`Time.timeScale = 0` でも期限後の `Update` で停止します。`Stop()`、無効化、終了、フォーカス喪失でも停止を要求します。切断後は古い参照を破棄します。再接続とフォーカス復帰では自動再開しません。

この例だけに振動の制御を任せてください。同じ接続を別の振動処理と共有すると、停止要求が他の出力も止めます。ライブラリの停止処理は、切断や読み取り失敗も扱います。

画面の「API 受付」は物理応答の証拠ではありません。合成実行と参照コンパイルでロジックを確認します。Unity Play、画面表示、実機の振動と停止は別途確認が必要です。

```powershell
pwsh -NoProfile -File Tools/Test-RumbleSample.ps1
```
