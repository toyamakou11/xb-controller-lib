# ゲームイベントの振動

発射、反動、被弾のイベントを #12 の振動制御へ接続します。汎用効果エンジンは追加しません。

## 導入

1. Package Manager で「モーター別の振動」を Import します。
2. 「ゲームイベントの振動」を Import します。
3. GameObject に `RumbleExample` を追加します。
4. 同じ GameObject に `EventRumbleExample` を追加します。
5. `rumble` にその `RumbleExample` を割り当てます。
6. Play で画面右側のイベントボタンを押します。

ゲームからはイベントが発生した時に `Fire()`、`Recoil()`、`Hit()` を呼びます。ボタン保持中の毎フレーム呼び出しは避けてください。

## 強度と時間

| イベント | 本体低周波 | 本体高周波 | 左トリガー | 右トリガー | 秒 |
| --- | --- | --- | --- | --- | --- |
| 発射 `Fire` | 0.1 | 0.15 | 0 | 0.4 | 0.08 |
| 反動 `Recoil` | 0.3 | 0.2 | 0 | 0.6 | 0.15 |
| 被弾 `Hit` | 0.7 | 0.4 | 0.3 | 0.3 | 0.35 |

対応情報で各出力を制限します。Unity Gamepad 経路は本体2モーターを使います。要求するモーターが全て非対応なら拒否します。

## 重なりと停止

最後に API が受け付けたイベントが出力と期限を置き換えます。合算、優先度、待ち行列はありません。同じフレームの発射→反動では反動が残ります。被弾の後に発射を受け付けた場合も、発射で置き換えます。

同じ `RumbleExample` で API が拒否したイベントは、既存の出力と期限を保持します。制御例を変更する場合は、以前の出力を先に停止します。

期限と切断・フォーカス喪失の停止は #12 を使います。`Stop()`、無効化、終了でも、この例が開始した出力を停止します。復帰や再接続では自動再開しません。

この例専用の `RumbleExample` を使ってください。地面振動、手動ボタン、別の振動処理と出力を共有しないでください。戻り値 `true` と画面の「API 受付」は物理応答の証拠ではありません。

```powershell
pwsh -NoProfile -File Tools/Test-EventRumbleSample.ps1
```

合成実行と Unity 参照コンパイルで確認します。Unity Play、Import、画面表示、実ゲームのイベント接続、実機応答は別途確認が必要です。
